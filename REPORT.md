# ОТЧЁТ ПО ПРАКТИЧЕСКОЙ РАБОТЕ
## Тема: Создание и развитие веб-сайта с помощью Git и GitHub

**Тема проекта:** VOLT — интернет-магазин спортивной одежды.

**Цель:** разработать многостраничный адаптивный сайт, сохранить его в GitHub, выполнить изменения в отдельных ветках и опубликовать через GitHub Pages.

### Описание выполненной работы
Создан сайт в чёрном и неоново-зелёном стиле. Главная страница содержит навигацию, баннер, описание бренда, преимущества, избранные товары и подвал. Каталог содержит шесть демонстрационных товаров и фильтры. Корзина позволяет добавлять и удалять товары, отображает количество и итоговую сумму. Данные корзины сохраняются в браузере с помощью localStorage.

### Структура проекта
- `index.html` — главная страница.
- `catalog.html` — каталог товаров.
- `cart.html` — корзина.
- `style.css` — общий адаптивный дизайн.
- `script.js` — фильтрация каталога и работа корзины.
- `README.md` — описание проекта.
- `.gitignore` — исключения Git.

### Этапы Git
1. В `main` создана начальная версия сайта.
2. В `feature/second-page` добавлена страница каталога и навигация.
3. В `feature/responsive` выполнена адаптация под телефон и планшет.
4. После объединения веток проверена итоговая версия.

### Команды Git
```bash
git init -b main
git add .
git commit -m "Создана начальная версия сайта"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main

git switch -c feature/second-page
git add catalog.html
git commit -m "Добавлена страница каталога"
git add index.html catalog.html
git commit -m "Настроена навигация сайта"
git push -u origin feature/second-page

git switch main
git pull --ff-only origin main
git switch -c feature/responsive
git add style.css
git commit -m "Добавлен адаптивный дизайн"
git add style.css script.js cart.html
git commit -m "Улучшена мобильная версия и добавлена корзина"
git push -u origin feature/responsive
```

На GitHub необходимо создать два Pull Request: `feature/second-page` → `main` и `feature/responsive` → `main`, проверить вкладку Files changed и выполнить Merge. После каждого объединения обновить локальную `main`.

### Проверка сайта
Проверить переходы между страницами, работу фильтров каталога, добавление и удаление товаров в корзине, отображение итоговой суммы, адаптивность на телефоне и компьютере. После публикации проверить все страницы через GitHub Pages.

### Результат
Подготовлен многостраничный адаптивный сайт VOLT. Исходный код, README и отчёт готовы. Ссылки на репозиторий, два объединённых Pull Request и GitHub Pages добавляются после выполнения действий в личном аккаунте GitHub.

## Контрольные вопросы

**1. Чем отличаются Git и GitHub?**  
Git — система контроля версий, а GitHub — онлайн-платформа для хранения репозиториев и совместной разработки.

**2. Что хранится в папке `.git`?**  
История коммитов, ветки, настройки и служебные данные репозитория.

**3. Что такое staging area?**  
Область подготовленных изменений. Команда `git add` помещает файлы в неё перед коммитом.

**4. Чем отличаются `git commit` и `git push`?**  
`git commit` сохраняет изменения локально, а `git push` отправляет коммиты на GitHub.

**5. Как посмотреть состояние файлов и ветки?**  
`git status` показывает состояние файлов, `git branch` — список веток.

**6. Почему изменения выполняются в отдельной ветке?**  
Чтобы работать над новой функцией отдельно и не нарушать основную версию проекта.

**7. Чем Pull Request отличается от коммита?**  
Коммит сохраняет изменение, а Pull Request предлагает проверить и объединить изменения ветки.

**8. Что означают base и compare?**  
`base` — ветка, куда вливаются изменения; `compare` — ветка с предлагаемыми изменениями.

**9. Для чего выполняют `git pull` после Merge?**  
Чтобы получить объединённые изменения с GitHub в локальную ветку.

**10. Как посмотреть различия между версиями?**  
Командой `git diff`, например `git diff HEAD~1 HEAD`.

**11. Что включают в README.md?**  
Название, назначение, страницы, технологии, инструкцию запуска и ссылку на публикацию.

**12. Почему абсолютные пути могут не работать на GitHub Pages?**  
Потому что проект может находиться во вложенной папке сайта. Относительные пути обычно работают надёжнее.

**13. Почему нельзя публиковать токены и пароли?**  
Посторонние могут использовать их для доступа к аккаунтам и сервисам.

**14. Как доказать этапы разработки по истории Git?**  
Показать коммиты, ветки, сравнение изменений и два объединённых Pull Request.
